The skill instructs Claude to perform this workflow when `/review` is invoked:

**Step 1: Check for today's review file**
Look for `data/review/YYYY-MM-DD.md` (today's date). If it exists, read it and display a summary to Robin: "Today's pulse found {N} ideas from {sources}. Here's the overview:" followed by a brief listing. If no file exists, tell Robin: "No pulse has run today. Run /pulse first, or reviewing ideas from previous days."

**Step 2: Query pending ideas from database**
Run via Bash:
```bash
node -e "
  require('dotenv').config();
  const db = require('better-sqlite3')('data/content.db');
  const ideas = db.prepare(\"SELECT id, title, summary, source_url, source_type, score, status, transcript FROM ideas WHERE status IN ('new', 'starred') ORDER BY score DESC\").all();
  console.log(JSON.stringify(ideas));
  db.close();
"
```

If no ideas returned, tell Robin: "No pending ideas to review. All caught up!"

**Step 3: Present ideas and collect decisions**

For each idea, present it in this format (per D-09 — NO score breakdown shown):

```
--- Idea {N}/{total} ---

{title}

Source: {source_type} | {source_url}
Angle: {content_angle_suggestion}

> {summary}

[Transcript available: {yes/no}]
```

Content angle suggestion logic (same heuristic as review-generator.js):
- source_type === 'changelog' -> "News reaction"
- title contains "tutorial", "how to", "guide", "learn" -> "Tutorial breakdown"
- title contains "wrong", "actually", "unpopular", "hot take", "controversial" -> "Hot take"
- title contains "vs", "compare", "comparison", "better" -> "Comparison"
- default -> "Topic breakdown"

After presenting each idea, use `AskUserQuestion` to ask Robin:
"**KEEP** (generate content) / **SKIP** (dismiss) / **STAR** (save for later) / **QUIT** (stop reviewing)"

Accept inputs case-insensitively: k/keep, s/skip, st/star, q/quit.

**Step 4: Update status in database**

After each decision, immediately update the idea's status:
```bash
node -e "
  const db = require('better-sqlite3')('data/content.db');
  db.prepare('UPDATE ideas SET status = ? WHERE id = ?').run('{status}', '{id}');
  db.close();
"
```

Where `{status}` is `kept`, `skipped`, or `starred` based on Robin's choice.

**Step 5: Summary**

After all ideas are reviewed (or Robin quits), show a summary:
```
Review complete:
- Kept: {n} ideas (ready for content generation)
- Skipped: {n} ideas
- Starred: {n} ideas (will appear in next review)
- Remaining: {n} ideas (not yet reviewed)
```

**Important behavioral rules:**
- Per D-08: Decisions happen ONLY via this interactive /review command, NOT by editing the markdown file
- Per D-09: Show title + summary, source + link, and content angle. Do NOT show score breakdown
- Previously starred ideas appear alongside new ideas, sorted by score descending
- The `transcript` column content is available but not shown inline during review (it was in the markdown overview per D-12). If Robin asks about a specific idea's transcript, read it from DB and show it
- If Robin types "quit" or "q", stop the review loop immediately and show the summary
