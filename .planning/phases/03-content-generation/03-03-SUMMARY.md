# Phase 3 Plan 03: Content Orchestrator Summary

**One-liner:** Single-command orchestrator generates TikTok EN + DE, Instagram (1080x1350 crop), and LinkedIn drafts from any kept idea using Claude API voice profiles, saves all 4 platform drafts to content.db.

## What Was Built

`scripts/generate-content.js` — a 652-line CommonJS Node.js orchestrator that is the "one command -> 4 platform drafts" core of Phase 3.

### CLI Interface

```
node generate-content.js --idea <idea_uuid> [--linkedin-format carousel|text|infographic|personal]
```

### Full Pipeline (12 Steps)

1. **UUID validation** (T-03-11): Validates `--idea` argument matches UUID format before any path construction.

2. **DB lookup**: Reads the kept idea from `content.db` including `idea.visual_approach` (Robin's KEEP-time choice per D-02).

3. **Visual approach resolution** (D-02): Reads `idea.visual_approach` from DB. Falls back to `catalog.photos.length > 0 ? 'photo_overlay' : 'ai_generated'` only when DB value is NULL (ideas kept before Phase 3).

4. **Output directory creation**: Creates `media/output/<idea_id>/tiktok-en/`, `tiktok-de/`, `instagram/`, `linkedin/`.

5. **Voice profile loading**: Reads `voice-casual.xml` and `voice-linkedin.xml` before any generation. (Per writing/SKILL.md: "NEVER generate content without reading the voice profile first.")

6. **TikTok EN content generation**: Claude API (`claude-sonnet-4-20250514`) generates 3-8 slides with text, photo descriptions, caption, and hook formula. Response wrapped in `safeJsonParse()` (T-03-09).

7. **TikTok EN slide rendering**: Routes by visual approach:
   - `photo_overlay`: keyword-matches slides to catalog photos, calls `generate-tiktok-slides.js`
   - `ai_generated`: calls `generate-ai-slides.js` for base images, then `generate-tiktok-slides.js` for text overlay

8. **TikTok DE localization** (D-09/D-10): Claude API with `<localization-de>` rules from `voice-casual.xml`. Reuses EN photo paths (`photos.json`) — only text changes.

9. **Instagram carousel** (TIKT-07): `sharp().resize(1080, 1350, { fit: 'cover', position: 'centre' })` on each TikTok EN PNG. No second render. No German version (D-11).

10. **LinkedIn content**: Claude API with `voice-linkedin.xml` generates post text. For carousel format, also generates `SLIDES_JSON:` array inline. Calls `generate-linkedin-content.js` with `--post-text` and optionally `--slide-texts`.

11. **Draft persistence**: Inserts 4 rows into `drafts` table with `status='generated'`, `visual_approach`, `media_dir`, and JSON content payload.

12. **JSON summary**: Prints full summary to stdout with idea ID, platform list, visual approach source, draft UUIDs, output directory.

### Security Implementation (Threat Model)

- **T-03-09 (JSON parse):** `safeJsonParse()` helper wraps every `JSON.parse` on Claude API responses. Strips markdown code fences first, catches parse errors, logs raw response (first 500 chars), exits with status 1.
- **T-03-10 (API key exposure):** `ANTHROPIC_API_KEY` loaded via dotenv into `new Anthropic()` constructor only. Never interpolated into prompt text, slide content, draft JSON, or output files.
- **T-03-11 (path traversal):** UUID format validated with `/^[0-9a-f-]{36}$/` before `idea.id` used in any `path.join()`. Invalid UUIDs exit immediately with descriptive error.

### LinkedIn Format Auto-Suggestion (D-06)

`suggestLinkedInFormat()` implements heuristic routing:
- `tutorial|how to|guide|tips` in title or `tutorial breakdown` in content_angle → `carousel`
- `hot take|wrong|actually|controversial` in title or `hot take` in angle → `text`
- `source_type === 'founder_note'` or story angle → `personal`
- `news reaction` angle + numeric data → `infographic`
- default → `text` (safest fallback)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] safeJsonParse() helper for markdown-fenced JSON**
- **Found during:** Task 1 implementation analysis
- **Issue:** Plan specifies `JSON.parse(tiktokResponse.content[0].text)` directly, but Claude models frequently wrap JSON in markdown code fences (` ```json ... ``` `) even when instructed to return "valid JSON only". Direct parse would crash with SyntaxError.
- **Fix:** Extracted `safeJsonParse(text, label)` helper that: (1) strips markdown code fences via regex, (2) wraps in try/catch with descriptive error and raw response preview, (3) exits with status 1 on failure. Applied to all 4 Claude API JSON responses.
- **Files modified:** `scripts/generate-content.js`
- **Commit:** N/A (no git repo)

**2. [Rule 2 - Missing critical functionality] Slide count alignment for TikTok DE**
- **Found during:** Task 1 implementation
- **Issue:** If Claude's German localization returns a different number of slides than the English original, `generate-tiktok-slides.js` exits with "texts and photos arrays must be same length" error.
- **Fix:** After DE localization, pad (repeat last slide) or trim DE slides array to match EN slide count before writing `texts.json`.
- **Files modified:** `scripts/generate-content.js`
- **Commit:** N/A (no git repo)

**3. [Rule 2 - Missing critical functionality] AI slide path handling for DE reuse**
- **Found during:** Task 1 implementation
- **Issue:** In the `ai_generated` path, the plan writes `photos.json` with pre-overlay AI image paths but the overlay pass overwrites them in-place. The DE pipeline reads `photos.json` to get the raw photo paths, but these paths now point to overlaid images (text already baked in) — which would double-overlay.
- **Fix:** In the AI path: (1) write `photos.json` with raw AI image paths before the overlay pass, (2) use a separate `photos-ai.json` as input to the overlay pass. This keeps `photos.json` pointing to the clean base images that DE can reuse.
- **Files modified:** `scripts/generate-content.js`
- **Commit:** N/A (no git repo)

**4. [Rule 2 - Missing critical functionality] LinkedIn post text generated before calling generate-linkedin-content.js**
- **Found during:** Task 1 implementation — Plan 02 SUMMARY documents that text/personal/infographic formats return skeleton output when `--post-text` is absent.
- **Issue:** The plan's Step 10 calls Claude to generate post text but then doesn't properly wire it into `generate-linkedin-content.js` via `--post-text`. The skeleton stubs from Plan 02 would remain unfilled.
- **Fix:** Generate LinkedIn post text via Claude with `voice-linkedin.xml`, write to `post-text.txt`, pass via `--post-text` flag. For carousel format, parse `SLIDES_JSON:` suffix from response and pass via `--slide-texts`.
- **Files modified:** `scripts/generate-content.js`
- **Commit:** N/A (no git repo)
