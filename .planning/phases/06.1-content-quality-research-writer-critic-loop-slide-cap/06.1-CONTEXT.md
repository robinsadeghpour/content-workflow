# Phase 06.1: Content Quality — Research + Writer-Critic Loop - Context

**Gathered:** 2026-04-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Every `/generate-content` run produces drafts grounded in real research, and the writer-critic loop actually improves drafts (not the current shallow-merge behavior) before Robin sees them.

**In scope:**
- On-demand research pass (runs at `/generate-content` time, not during pulse)
- Writer-critic loop hardening: fix CR-01 `Object.assign` corruption, enforce iteration cap, platform-aware rubric
- Content economy enforcement ("no more slides/paragraphs than needed") inside the critic pass

**Out of scope:**
- Hard slide-count cap as a phase deliverable — replaced by critic cut-test heuristic
- Pulse-time research (too expensive; only researched ideas that actually get picked)
- Replacing the voice/humanizer pipeline (it stays; critic just stops re-scoring voice)

<decisions>
## Implementation Decisions

### Research Sourcing
- **D-01:** Research runs on-demand at `/generate-content` time, NEVER during pulse. Only ideas Robin picks get researched — avoids burning API calls on ideas that get skipped.
- **D-02:** NotebookLM is the primary synthesizer for transcript-heavy sources. Aim for high-value/high-information output, not broad web sweeping.
- **D-03:** Medium depth: 3–6 sources per idea.
- **D-04:** Freshness bias: last 30 days preferred. AI/tech moves fast; stale examples hurt credibility.
- **D-05:** Fallback when research finds nothing useful: warn and continue. Draft is generated anyway and flagged `research-thin` for Robin's awareness.

### Research Integration
- **D-06:** Research runs as the FIRST step in `/generate-content`, before any writer agent spawns. One research pass feeds all 4 platform drafts — consistent facts across TikTok EN/DE, Instagram, LinkedIn.
- **D-07:** Research artifact is a structured brief: key facts, 3–5 quotes/stats, sources list, angle suggestions. Writer picks what to use.
- **D-08:** Persistence path: `data/research/{idea_id}.md`. One file per idea, reusable across regenerate runs, visible in dashboard.
- **D-09:** Writer receives research by inlining the full brief into the writer agent prompt. No extra tool calls.

### Writer-Critic Loop
- **D-10:** Hard iteration cap: **2 revisions max per platform** (initial write → critique → revise → critique → revise → critique → final).
- **D-11:** Pass bar: **≥ 8/10 on every scored dimension**. Exit loop as soon as all dimensions clear.
- **D-12:** On max-iters hit: keep the **best-scored iteration** (not necessarily the last), pass it through with a `did-not-pass` flag so Robin sees which drafts failed the bar.
- **D-13:** On revise, writer receives **full critic feedback + the previous draft** and produces a new full draft. This replaces the buggy `Object.assign(content, revisedContent)` shallow-merge at `scripts/apply-critic.js:242` (CR-01). The reviser's output fully replaces `content`, not merges.

### Critic Rubric
- **D-14:** Critic scores exactly three dimensions: **Hook strength**, **Fact grounding**, **Slide/content economy**. Voice authenticity is dropped from the critic — it's already handled by the `/writing` + humanizer pass before the critic sees the draft.
- **D-15:** Per-platform rubric weights: TikTok weights hook + economy highest; LinkedIn weights fact-grounding highest. Each platform has its own weight vector.
- **D-16:** Fact grounding check: critic re-reads `data/research/{idea_id}.md` alongside the draft and flags any factual claim not supported by the brief. No inline citation markers required from the writer.
- **D-17:** Content economy enforcement: **cut-test per unit**. For each slide/paragraph the critic asks "if I removed this, would the draft be worse?" If not → recommend cut. No hard slide-count range; economy is a heuristic, not a fixed cap.

### Claude's Discretion
- Internal structure of the research brief markdown (headers, section order) — whatever makes downstream writers effective
- Per-platform weight values for the critic rubric — tune empirically, document in rubric file
- Writer-critic agent invocation shape (Task calls, file handoffs, etc.) — let planner decide based on existing orchestrator patterns
- How `research-thin` and `did-not-pass` flags are stored (column on drafts table, JSON side-file, etc.)

</decisions>

<specifics>
## Specific Ideas

- **NotebookLM preference:** Robin explicitly wants NotebookLM as the research engine for transcript-heavy sources — aim for high-value, high-info output, not broad scraping. It avoids valueless content.
- **On-demand only:** "Only when I want to use an idea, not before" — research must not run during pulse.
- **No hard slide cap:** Earlier framing included a slide-count cap; Robin rejected hard caps in favor of "generally not more than needed." The cut-test heuristic in the critic delivers this without a magic number.
- **CR-01 from 03-REVIEW.md is load-bearing** for this phase — the writer-critic loop can't work correctly until the shallow-merge bug is replaced with full reassignment.

</specifics>

<deferred>
## Deferred Ideas

- Pulse-time research pre-fetching for top-scored ideas (would save time at `/generate-content` but burns cost on ideas that get skipped — revisit if research becomes a bottleneck)
- Hard slide-count ranges per format — replaced by critic cut-test; revisit only if economy scores stay low across runs
- Inline citation markers (writer annotates draft with [R1]/[R2] pointers to brief) — rejected as noisy; revisit only if fact-grounding accuracy becomes a problem

</deferred>
