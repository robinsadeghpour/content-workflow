# Phase 06.1 Plan 02: Wire Orchestrator + Writer to Research + Fixed Critic Loop Summary

Orchestrator runs research first and propagates the brief to every writer; critic loop now enforces the 2-iter cap, replace-not-merge revise semantics, and best-iteration retention with flag persistence.

## What Was Built

### Task 1 — Step 1.5 Research Pass + brief propagation
- New `### Step 1.5: Research Pass (D-06)` section inserted between Step 1 (Load Idea) and Step 2 (Determine Visual Approach) in `content-orchestrator.md`.
- Pipeline: stage transcript to tmp file (if present) → `bash scripts/research/run-notebooklm.sh ...` → Read the brief file → parse `research_thin` frontmatter into orchestrator state → clean up tmp file.
- Fail-open per D-05: catastrophic failure of the research module falls back to a stub brief with `research_thin: true`, never blocks generation.
- Steps 5 (TikTok EN), 8 (TikTok DE), 12 (LinkedIn) — writer spawn input lists extended with two new bullets: `Research brief path: <BRIEF_PATH>` and `research_thin: <0 or 1>`.
- Step 11 (Instagram crop) intentionally does NOT receive the brief because it reuses TikTok EN content verbatim (D-11).
- **Commit:** `b5fb293`

### Task 2 — Critic Loop rewrite (replace-not-merge, 2-iter cap, best-iter retention)
- New `## Critic Loop (shared by Steps 6, 9, 13)` section placed before `## Workflow` so all three platform critic reviews point to one canonical spec.
- Explicit semantics:
  - Load `.claude/agents/data/critic-rubric.json` once for `pass_threshold`, `max_revisions`, and `weights[<platform>]`
  - Per-iteration: evaluate → pass-bar check (all three `>= 8`) → revision-cap check (`>= 2`) → revise → append to `iterations[]`
  - D-13 revise semantics: `"REPLACES the previous draft entirely. Do NOT merge, do NOT spread, do NOT preserve fields from the prior draft"` — the load-bearing CR-01 fix encoded directly in the spec
  - On max-iters hit: `argmax(iterations, weighted_score)` keeps the best-scored iteration; `did_not_pass_critic = 1`
- Steps 6, 9, 13 collapsed from inline critic pseudo-loops to single-line `"Run the Critic Loop (see shared spec above)"` references.
- Step 15 db-write-draft.js example gained conditional `[--research-thin]` / `[--did-not-pass]` flags plus prose explaining when to append each.
- Step 16 warning rewritten to match new loop behavior ("did not pass the critic bar — best-scored iteration kept").
- `## Error Handling` entry replaced: old "If critic fails all 3 attempts: mark as `critic_failed`" → new "keep the best-scored iteration and flag `did_not_pass_critic=true` — do NOT skip the draft".
- **Commit:** `1b130c6`

### Task 3 — Writer brief inlining (MANDATORY first read)
- `## Before Generating Anything` section in `writer.md` rewritten from a single MANDATORY line to an ordered `MANDATORY READS` list.
- Order (load-bearing per Pitfall 6 from RESEARCH): (1) Research brief, (2) Voice profile, (3) Storytelling framework.
- Brief-first rule is explicit: "Your output must only claim facts supported by the brief + the idea's title/summary/transcript. Check the frontmatter — if `research_thin: true`, note it in your SendMessage status."
- All three platform sections (TikTok EN, TikTok DE, LinkedIn) gained a new first input bullet: `Research brief path (data/research/<idea_id>.md) — read and inline this FIRST`.
- No frontmatter/tools changes — writer already has Read.
- **Commit:** `a221031`
