**Step 2: Create `scripts/perf-check.js`**

CommonJS script (`'use strict'`), loads dotenv from `../.env`.

**Logic:**

1. Open `data/content.db` with better-sqlite3.
2. Query all drafts with `status IN ('scheduled', 'published')` AND `postiz_id IS NOT NULL`.
3. For each draft:
   a. Call `spawnSync('npx', ['postiz', 'analytics:post', draft.postiz_id, '-d', '1'], { encoding: 'utf-8', env: { ...process.env } })`.
   b. Parse stdout as JSON.
   c. If result contains `missing === true`: log `[MISSING] Draft ${draft.id} (${draft.platform}) — TikTok release ID not yet resolved. Skipping.` and continue to next draft.
   d. If result is valid metrics data: extract `views`, `likes`, `comments`, `shares` from the response (normalize field names based on Postiz response format).
   e. Compute performance score using this formula (D-08):
      ```javascript
      function computePerformanceScore(views, likes, comments, shares) {
        if (!views || views === 0) return 0;
        const engagementRate = (likes + comments + shares) / views;
        return Math.min(1, Math.log10(engagementRate * 1000 + 1) / 3);
      }
      ```
   f. Insert or update performance record:
      ```sql
      INSERT INTO performance (id, draft_id, platform, views, likes, comments, shares, score, checked_at)
      VALUES (?, ?, ?, ?, ?, ?, ?, ?, datetime('now'))
      ON CONFLICT(id) DO UPDATE SET views=?, likes=?, comments=?, shares=?, score=?, checked_at=datetime('now')
      ```
      Use `${draft.id}-${new Date().toISOString().slice(0,10)}` as the performance record ID (one per draft per day).
   g. If draft status was `scheduled` and it has analytics data, transition to `published` (content was successfully published). If draft was `published` and now has tracked data, transition to `tracked`.
4. After processing all drafts, call `spawnSync('node', [path.join(__dirname, 'apply-performance-weights.js')], ...)` to update weights.
5. Generate daily summary markdown file.

**Step 3: Create `scripts/apply-performance-weights.js`**

CommonJS script (`'use strict'`).

**Logic (D-09, D-10):**

1. Open `data/content.db`.
2. Query performance data from the last 14 days (D-10):
   ```sql
   SELECT d.id, d.platform, d.topic_category, d.visual_approach, i.source_type, p.score
   FROM performance p
   JOIN drafts d ON p.draft_id = d.id
   LEFT JOIN ideas i ON d.idea_id = i.id
   WHERE p.checked_at >= datetime('now', '-14 days')
   ```
3. Group by `source_type` (topic proxy) and by `visual_approach` (format proxy).
4. For each group, compute average score.
5. Compute multiplier: `multiplier = clamp(avg_score / global_avg_score, 0.7, 1.5)` — scores above average get a boost (up to 1.5x), below average get a penalty (down to 0.7x). Use config values from `config/schedule-defaults.json` `perf_check.multiplier_max` and `perf_check.multiplier_min` if that config section exists, otherwise default to 0.7/1.5.
