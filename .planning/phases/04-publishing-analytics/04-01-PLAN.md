**Step 4: Create `scripts/approve-draft.js`**

CommonJS script (`'use strict'`), loads dotenv from `../.env`.

**CLI interface:**
- `--id <draft_id>` — target draft ID
- `--action <approve|reject|edit>` — what to do
- `--schedule-at <ISO8601>` — optional custom schedule time (D-06)
- `--content <text>` — replacement content for edit action (D-04)
- `--list` — list all critic-approved drafts (for /approve skill to display)
- `--list-pending` — list all pending-schedule drafts for retry
- `--platform <linkedin|tiktok_en|tiktok_de|instagram>` — optional filter for --list (D-01)

**State machine (D-12, D-13):**
```javascript
const VALID_TRANSITIONS = {
  'draft':            ['critic-approved'],
  'critic-approved':  ['user-approved', 'rejected'],
  'user-approved':    ['scheduled', 'pending-schedule'],
  'pending-schedule': ['scheduled'],
  'scheduled':        ['published'],
  'published':        ['tracked'],
};

function transitionDraft(db, draftId, toStatus) {
  const draft = db.prepare('SELECT status FROM drafts WHERE id = ?').get(draftId);
  if (!draft) throw new Error(`Draft ${draftId} not found`);
  const allowed = VALID_TRANSITIONS[draft.status] || [];
  if (!allowed.includes(toStatus)) {
    throw new Error(`Invalid transition: ${draft.status} -> ${toStatus} for draft ${draftId}`);
  }
  db.prepare("UPDATE drafts SET status = ?, updated_at = datetime('now') WHERE id = ?")
    .run(toStatus, draftId);
}
```

**--list mode:** Query drafts with `status = 'critic-approved'` (optionally filtered by `--platform`). For each draft, parse `content` as JSON and extract display text:
- `tiktok_en`/`tiktok_de`/`instagram`: `JSON.parse(content).caption`
- `linkedin`: `JSON.parse(content).post_text`
- Include: draft.id, draft.platform, display text (first 200 chars), critic voice_score from the content JSON if present, draft.visual_approach, slide count if applicable.
Output as structured JSON array to stdout.

**--list-pending mode:** Query drafts with `status = 'pending-schedule'`. Output as JSON array with id, platform, error info.

**--action approve:**
1. Validate draft status is `critic-approved`. Call `transitionDraft(db, id, 'user-approved')`.
2. Compute schedule time: if `--schedule-at` provided, use that (D-06). Otherwise, call `nextSlotForPlatform(draft.platform)` using date-fns + @date-fns/tz TZDate.
3. Upload media if platform is tiktok_en, tiktok_de, or instagram AND draft.media_dir exists:
   - Read slide files from `draft.media_dir` matching `/^slide-\d+\.(png|jpg|webp)$/`
   - For each file: `spawnSync('npx', ['postiz', 'upload', filePath], ...)` — parse stdout JSON for `.path` (CDN URL)
   - Collect CDN URLs into array
4. Read integration_id from `config/schedule-defaults.json` for the draft's platform.
5. Extract post content text from `drafts.content` JSON (caption or post_text).
6. Call `spawnSync('npx', ['postiz', 'posts:create', '-c', contentText, '-s', scheduleISO, '-i', integrationId, ...mediaPaths ? ['-m', mediaPaths.join(',')] : []], ...)`.
7. On success: parse returned JSON for postiz post ID, update `drafts.postiz_id`, call `transitionDraft(db, id, 'scheduled')`. Print success with schedule time.
8. On failure: call `transitionDraft(db, id, 'pending-schedule')`, store error in stdout, print warning but DO NOT throw (D-07 — loop continues).

**--action reject (D-14):**
1. Validate draft status is `critic-approved`.
2. Call `transitionDraft(db, id, 'rejected')`.
3. Print confirmation.

**--action edit (D-04):**
1. Validate draft status is `critic-approved`.
2. Read current `drafts.content` JSON, parse it.
3. Replace the text field (`caption` or `post_text` depending on platform) with `--content` value.
4. Write updated JSON back to `drafts.content`.
5. Call `transitionDraft(db, id, 'user-approved')`.
6. Then proceed with scheduling exactly as --action approve step 2 onward (auto-schedule after edit per D-04).

**nextSlotForPlatform function (D-05):**
```javascript
const { setHours, setMinutes, addDays, isBefore } = require('date-fns');
const { TZDate } = require('@date-fns/tz');

function nextSlotForPlatform(platform) {
  const config = require('../config/schedule-defaults.json');
  const platformConfig = config.platforms[platform];
  if (!platformConfig) throw new Error(`Unknown platform: ${platform}`);
  const { default_hour, default_minute, timezone } = platformConfig;

  const nowInTz = new TZDate(new Date(), timezone);
  let candidate = setMinutes(setHours(nowInTz, default_hour), default_minute);
  if (isBefore(candidate, nowInTz)) {
    candidate = addDays(candidate, 1);
  }
  return candidate.toISOString();
}
```

**Retry logic for --list-pending:** When called with `--list-pending`, also attempt to reschedule each `pending-schedule` draft (same logic as approve steps 2-8), up to `config.retry.max_attempts` total attempts. Track attempt count in a `retry_count` field or simply attempt once per invocation.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input -> approve-draft.js | --content flag passes user text to DB and Postiz API |
| approve-draft.js -> Postiz CLI | Subprocess call with user-influenced content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | approve-draft.js state machine | mitigate | Validate current state before transition — VALID_TRANSITIONS map prevents skipping approval gate |
| T-04-02 | Tampering | --content flag injection | accept | Robin is the only user; content goes through Postiz CLI which handles escaping; low risk for single-operator system |
| T-04-03 | Repudiation | Draft approval actions | mitigate | All state transitions write updated_at timestamp; drafts table preserves full history; rejected drafts kept in DB (D-14) |
| T-04-04 | Information Disclosure | config/schedule-defaults.json with integration IDs | mitigate | Add config/ to .gitignore if not already present; integration IDs are not secrets but are environment-specific |
| T-04-05 | Denial of Service | Postiz API rate limiting | mitigate | pending-schedule state + retry with backoff (D-07); max_attempts cap in config |
| T-04-06 | Elevation of Privilege | Direct DB status manipulation | accept | Single-operator CLI system; no multi-user access control needed |
</threat_model>
