## Post LI-005

This cancellation flow changed how I think about churn...

As an early-stage product, our goal is to solve churn (and hopefully find product-market fit)

And oh damn... churn is a b*tch

But, a proper cancellation flow can help you understand churn (and maybe even reduce it???)

Here's the flow I implemented for Postel:

1. Offer a pause instead of cancel: 
Life gets busy. Sometimes, people just need a break. 
→ Offer a 1-3 month pause 
→ Captures users before they fully churn

2. Ask why they're leaving: 
Use multiple choice options (from your data and assumptions) plus a required text field and an "other" option. (Multiple choice gets way more responses than free text)

3. Ask what they liked: 
After asking why they're leaving, we ask what they enjoyed (multiple choice). 
→ Creates a pause in the cancellation flow 
→ Shows what actually delivered value 
→ 81% gave us feedback - mostly content quality, UX, and support

4. Conditional support call: 
If someone picks "too difficult" or "content quality," we offer a 15-min call. 
→ Only if we can actually help 
→ Skippable so it doesn't feel forced 
(tip: feel free to incentivize user to hop on calls (e.g., gift cards, usage credits) to get higher participation and richer feedback)

5. Targeted retention:
 offer 30% off for 3 months; tailored to their reason. 
→ Budget issues? Here's a discount 
→ Other issues? Offer comes after we listen

6. Clean, respectful exit: 
Clean, respectful exit Remind them what features they'll lose access to (people often forget what they had). Otherwise, make it guilt-free.
→ Access continues until billing ends 
→ Follow-up email with thanks + discount link

One thing: 
The whole flow isn't skippable. Might be annoying, but 97% of users gave us feedback (135 out of 139 cancellations) and it's invaluable at our stage.

The insights: 
Most cancellations came from users who were never going to convert.

Top reasons:
• Pricing (but not willing to pay for any tool)
• Content quality (kinda fair, we're early)
• Taking a break (these we can often save)

This led us to kill freemium and switch to a 7-day trial with credit card. 
(now we have more high intent signups and less churn)

Takeaway: 
A cancellation flow won't fix bad product-market fit. But it will reveal it. We saved a few users. The real win, tho? Understanding who shouldn't have signed up in the first place.

How are you handling churn? 
Would love to hear what's worked.

## Post LI-012

You need to write docs

Seriously. It's a game changer for AI-coding

Here's what to document and how:

architecture/
→ Use Architecture Decision Records (ADRs) to document every key choice and why it was made

features/
→ Keep specs, PRDs, and feature docs here. AI agents can build from them or debug features instantly

integrations/ 
→ Drop specific API docs here. No need for global search, just reference what matters, fast

guides/ 
→ Best practices and step-by-step how-to's. I even keep guides for AI workflows (agents, hooks, etc.)

incidents/ 
→ Postmortems live here. If an old bug shows up again, you'll know the backstory

archive/ 
→ Store old projects, finished docs, and anything else worth keeping. Never lose the context

Use Claude hooks to keep everything up to date

Reference these docs in cursor-rules.md or claude.md

And most importantly, prompt your agent with the right docs as context

## Post LI-035

I built a fully automated pipeline that turns YouTube videos into LinkedIn posts.

One command kicks it off. yt-dlp searches YouTube from the terminal, pulls back titles, view counts, channels, durations. The top results get pushed straight into Google NotebookLM via notebooklm-py, an unofficial Python CLI someone built because Google never shipped a real API.

NotebookLM pulls captions, indexes everything, and lets me query across all the videos at once. Google handles the retrieval side and it's free.

The pipeline queries the notebook for key insights. It answers with specifics tied to the actual captions. If something isn't in the source material, it doesn't come back.

Then Claude Code takes that research and writes the post. Most of the work is already done at that point. The post itself is the fast part.

Whole thing runs in my terminal. No browser tabs. No pasting transcripts into chat windows. No re-watching anything.

Three tools make this work:
→ yt-dlp (github.com/yt-dlp/yt-dlp)
→ notebooklm-py (https://lnkd.in/dg2fZtFt)
→ Claude Code

Used to take me a couple hours. Now it's one command and about fifteen minutes, and every claim traces back to the original video.

## Post LI-036

I tested three agentic frameworks to see if any of them actually make Claude Code better.

BMAD, Ruflo, and Superpowers. The core problem I wanted to solve: Claude forgetting what it's doing halfway through a big task.

Ruflo is the heaviest by far. Agent swarms, its own vector storage, a memory system so agents recall decisions across sessions, task graphs with dependency management, parallel execution. You're not configuring a tool at that point, you're maintaining a platform on top of your actual project. For a solo dev or small team that's a lot of overhead to manage something that's supposed to save you time.

BMAD takes a different approach — simulates an Agile team through rule files. PO agent writes stories, dev agent implements, reviewer agent gates the merge. In practice you drown in markdown. I spent more time reading generated specs than writing code.

Superpowers is what I kept. It plugs into Claude Code and forces the agent to brainstorm before jumping into implementation, debug systematically instead of guessing. No orchestration layer, no vector DB, no config sprawl. It stays out of the way.

I don't need swarm orchestration. I need the agent to stop and think for two seconds before rewriting my entire file. That's what Superpowers does and why the other two didn't stick.

## Post LI-039

Here's the ultimate paywall guide:

I’ve reverse-engineered the best consumer app paywalls out there (Duolingo, Headspace, Blinkist…)

They all share a few simple elements:

1. Feature Overview
List the core features, highlight the differences between plans, and keep it simple so the user doesn’t get overwhelmed.

2. The Pre-Selected Plan Trick
→ Show only one recommended plan with a line like “based on your needs”
→ You can personalize this based on onboarding
→ It removes decision fatigue - people don’t have to compare or think

3. Repeat the Trial Benefits
You’ll see “cancel anytime” and “free for 7 days” over and over.
This reduces the fear of accidental charges.
Sending a reminder email before the trial ends removes even more anxiety.

4. The Timeline Graphic
It shows exactly when the trial starts, when you’ll get notified, and when it ends.
This removes most of the sketchy paywall vibe and makes the whole thing feel predictable 

5. Testimonial Under the Timeline
Someone like Adam talking about how fast he got value.
It makes the app feel safe and proven - taking even more anxiety away and reminding users why they should subscribe.

6. Crystal Clear Billing
Show the price, the exact charge date, and highlight the yearly plan with the savings.
This gently anchors people toward the better option.
$0 for 7 days on both plans reinforces that there’s no risk right now.

Overall:
The whole setup feels simple, safe, and transparent.
No tricks - just a clear nudge toward the option that makes the most sense.

(We definitely stole a bunch of this for our own paywall redesign.)
